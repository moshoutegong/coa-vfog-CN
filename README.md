**CoAVolFog（体积雾与水面）** 为《魔兽世界》3.3.5a（12340）Direct3D 9 客户端添加体积雾和新版水面效果。原项目由 jealous-sound 开发。这个 fork 提供游戏内 **Ctrl+F7** 设置窗口的简体中文界面。

### 画面效果

- **体积雾**会随地形、时间和天气变化。经典版光照数据覆盖的区域使用对应的雾层，其他区域根据客户端的昼夜光照推算雾效。
- **光照**会在雾中散射，形成日月光晕。附近的点光源也能照亮雾气。进入建筑或洞穴时，室外雾和直射光会随镜头位置减弱。
- **新版水面**为湖泊、河流、海洋和室内水池加入波浪、折射、泡沫、倒影及日月高光。角色、生物、宠物和坐骑涉水时会产生涟漪和尾流。
- **可选效果**包括阳光光束、Forever 辉光、色彩分级、半透明特效雾和经典版散射能量归一化。雾与水面在驱动支持复制多重采样深度时可保留游戏的多重采样抗锯齿。

### 下载安装

从[最新发布](https://github.com/moshoutegong/coa-vfog-CN/releases/latest)下载 `CoAVolFog-Win32.zip`。也可在[汉化版构建页面](https://github.com/moshoutegong/coa-vfog-CN/actions/runs/43427238623)的 **Artifacts** 下载 `CoAVolFog-Win32-…`。压缩包里的 `BUILD.txt` 记录构建提交和验证范围。

1. 完全退出游戏。使用 ArdenWoW 登录器时，先关闭它的「Volumetric fog and water」并完成原版模组的移除，再手动安装。登录器会核对它管理的文件，手动安装的汉化版可能会显示为冲突。
2. 将 `version.dll`、`CoAVolFog.dll`、`fogdata.bin` 和 `waterdata.bin` 放到游戏可执行文件所在目录。
3. 首次安装时，同时放入 `CoAVolFog.ini`。已有配置时先保留原文件，以便继续使用自己的设置。如果目录里有其他模组使用的 `version.dll`，请先确认该文件的用途再替换。
4. 重新进入游戏，按 **Ctrl+F7** 打开设置。卸载时，在退出游戏后移除手动安装的 `version.dll` 和 `CoAVolFog.dll`。

### 游戏内设置

- **Ctrl+F7** 打开或关闭设置窗口。笔记本电脑若默认将 F7 当作媒体键，可试 **Ctrl+Fn+F7**。快捷键也可以在 `CoAVolFog.ini` 中通过 `OverlayKey` 修改。
- 画质、雾层与密度、光照、水面等选项带有中文悬停说明。大部分修改会在下一帧预览。点击 **保存** 才会把修改写入 `CoAVolFog.ini`，点击 **还原** 可重新读取文件。
- 可拖动窗口标题栏移动窗口，也可拖动右下角改变大小。窗口会在本次游戏会话中记住位置和尺寸。按住 **Ctrl** 单击滑块可直接输入数值。
- 窗口显示雾与水面的渲染状态，以及抗锯齿启用情况。启用多重采样后需重启游戏。关闭多重采样会在下一次重置显示时生效，例如调整游戏分辨率时。
- `Enable`、`EngineHooks`、`Overlay` 和 `OverlayKey` 可在配置文件中调整。所有配置键及其默认值见[配置项速查](#配置项速查)。

### 从源码构建

需要 Visual Studio 2022 的 x86 C++ 工具链、包含 `fxc.exe` 的 Windows 10/11 SDK，以及 CMake 3.20 或更新版本。首次配置会下载固定版本的 Dear ImGui。

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A Win32
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

构建文件位于 `build/Release`。简体中文字形内嵌在 `CoAVolFog.dll` 中，字体授权见 [CoAVolFog Sans 许可证](data/CoAVolFogSans-OFL.txt)。`ctest` 的完整检查需要可用的 D3D9 设备。只运行无需显卡的检查时，在 CTest 命令末尾加 `-LE gpu`。

如果使用 `gxApi d3d9ex` 或显卡不支持 INTZ 深度纹理，雾效与设置窗口可能无法显示。帧率下降时，可分别调低雾效的 **画质** 和 **水面画质**。

## 渲染原理

### 雾效、光照与合成

体积雾以四分之一或一半分辨率进行光线步进，由 `Quality` 决定。每一步只对它和雾层起止距离重叠的区间积分，使薄雾层和边界处不足一步的区间在不同画质下仍能得到接近的结果。只有实际上传了点光源或遇到带原始噪声的经典版雾层时，才启用对应的着色器变体。

`Temporal` 大于 0 时，采样位置逐帧变化并通过时域滤波累积。历史样本来自不同表面深度或深度类别（场景、远处地形或天空）时会被丢弃。动画光照变化时会降低历史权重，设置、地图、屏幕特效槽、投影或镜头发生较大变化时会清空历史。没有有效历史的像素改用低分辨率 3×3 邻域中位于同一表面的当前样本。设为 0 时使用固定中点采样并跳过时域处理，静止画面不会因逐帧抖动而闪烁。

合成阶段将雾效放大到完整分辨率，并检查邻近样本的深度。斜视地面时，若样本共面、雾沿样本线性变化且光线未穿过点光源范围，可使用当前帧的插值结果。如果低分辨率采样全部错过细小轮廓，则以完整分辨率重新积分。全屏处理使用一个边缘超出视口的三角形，以覆盖边缘像素的多重采样位置。

模组最多捕获八个附近的 M2 点光源。在线性光照模式下，最亮通道超过 1 的颜色按 `(c/peak)^2.2 · peak` 转换，保留动画强度。点光源共用 Henyey–Greenstein 相位参数 `LocalLightPhase`，朝向光源时的峰值归一到 1。

通常在场景几何和原版日月眩光之后、屏幕特效和界面之前绘制雾。绘制体积雾的帧会暂时把原版线性雾推到视距之外，随后恢复。客户端的全屏辉光公式为 `screen + g·blur²`，因此 `GlowCompensation` 用当前辉光强度补偿雾的颜色，避免日晕附近泛白。阳光光束需要场景副本，并利用辉光处理后剩余的高光范围。

### 辉光、调色与半透明特效

- `ForeverGlow=1` 时，经典版光照权重超过一半才开始把客户端的辉光混合到 Forever 光源的辉光值。混合权重为 `saturate((coverage − 0.5)/0.5)`。模组在雾合成前写入当帧的辉光字节，帧结束后恢复，灵魂视角下跳过覆盖。
- `ColorGrading` 用每通道 32 点的色彩曲线处理场景视口，按 `ColorGrading · t` 混合原色和调色结果。角色名字、界面、灵魂视角和水下画面跳过调色。
- `TransparentFog=1` 时，水面之上会在液体处理结束后提前绘制眩光和雾。后续半透明 M2 批次按自身平面视深应用线性雾。线性雾使用 100 码内 15 条采样光线的体积透射率做最小二乘拟合，并带入散射颜色和点光源。叠加、正片叠底和双倍正片叠底批次分别保留黑、白、灰。水下、关闭 `StockFog`、显示调试视图或太阳位置标记，以及提前合成不可用时，改在整个场景绘制结束后处理雾。

### 水面与涟漪

液体渲染前，模组复制场景颜色与线性深度，清理模板缓冲，并开启深度写入。原版水面按湖泊、河流、海洋和室内水域分类，并在模板缓冲中标记像素。液体渲染结束后，模组复制水面深度，按类别分别运行波浪模拟和全屏着色。水面先于天气、透明模型和体积雾处理，因此水面上的雾按水面自身深度计算。没有待绘制水面的帧会跳过这一步。

波浪使用 GPU FFT，基于 Tessendorf/Phillips 频谱和 Forever 的图块参数。网格为 128² 或 256²，统一按 256² 归一化波高，并输出坡度、坡度方差和泡沫状态。水面着色使用 Beer–Lambert 吸收、Henyey–Greenstein 散射和 EnvBRDF 反射权重。太阳高光以 GGX 近似，场景倒影沿屏幕空间步进，读取水面渲染前复制的场景。

涟漪用随镜头目标移动的 G16R16F 双缓冲贴图保存当前与上一时刻高度。每一步根据四邻域和上一时刻高度更新，公式为 `next = 0.97·edge·(0.5·(L + D + R + U) − C.g)`。角色与水面接触时按浸没程度、移动速度和接触范围写入波源。静止时水面趋于平静，跑动或游泳会形成 V 形尾流，起步和停下会各形成一圈涟漪。关闭 `WaterClientSplashes` 后，现代涟漪运行期间会暂时将客户端的 `waterRipples` 置为 0，结束时恢复。

### 多重采样与视距

D3D9 纹理无法直接保存多重采样深度。模组通过 NVIDIA 的 `NvAPI_D3D9_StretchRectEx`，或 AMD、Intel 等驱动提供的 `RESZ`，将多重采样深度复制到 `INTZ`。深度格式用带模板缓冲的 D24S8 替代 D24X8。创建设备时先复制两个已知深度做自检，失败就回退到单采样。

水面按每个采样位置标记和着色。雾只能读取每个像素的一份深度副本。对于邻域深度不共面的轮廓像素，会在近远深度之间设分界，用模板缓冲区分两侧并分别计算雾，最后按覆盖率混合。只有少数采样点覆盖的细小轮廓可能在复制时丢失。

Ascension 将东部王国、卡利姆多、外域和诺森德的视距限制在约 791.66 码。开启 `FarClipMax` 可提高到引擎支持的约 1583.33 码。地形加载、WDL 地平线和雾随视距变化，场景物件仍按 `environmentDetail` 的尺寸分类裁剪，生物可见距离由服务器控制。

## 数据来源与生成

### 经典版雾效数据

`tools/convert_classic_fog.py` 将 WoW Forever 1.60.1.70009 的雾效与光照资料包转换为 `data/fogdata.bin`。输入包括已解码的 `LightData`、`LightDataGlobalVolumeFog`、`LightParams`、`ZoneLightPoint` 和调色查找表，转换器会核对资料包的 SHA-256 清单以及雾表布局哈希 `24290E20`。灯光位置和区域光轮廓可从旧版二进制文件继承，也可从经典版客户端导出的 `Light.csv`、`ZoneLight.csv` 读取。

```powershell
python tools/convert_classic_fog.py <资料包目录或ZIP> --placements data/fogdata.bin data/fogdata.bin
```

转换器保留标志位 3 指定的雾层及其 0–2 层索引。运行时先按球形光源的衰减距离混合，再把剩余权重分配给包含镜头的区域光，区域边缘有 100 码过渡，重叠时最内层优先。其余权重归地图全局光。天气在晴朗槽 0 和风暴槽 2 间插值，屏幕特效可强制指定槽位，灵魂视角使用槽 4。相邻时间关键帧插值后，按原雾层索引配对。

经典版光源占混合权重至少一半时应用经典版雾层。当前槽位缺少雾层的光源按零密度参与混合，远景雾负责遮住视距边界。数据转换包含密度乘 0.01、按标志使用相对玩家的高度及地平线以下的阴影颜色与密度，并应用 `1 + strength·((d − start)/range)^exponent` 距离曲线。日光散射按旧客户端与经典版直射光的亮度比校准，比例上限为 1。

`ClassicPhase=1` 启用推算的能量归一化系数 `(1+g)/(4π(1−g)²)`，计算时将 `g` 限制在 0.95 以下。带标志位 2 的雾层使用两层可平铺三维 Perlin 噪声、固定 S 曲线和随时间漂移的采样相位，使风暴雾更有层次，平均密度约减半。没有原版噪声纹理时，模组使用加载时生成的 64³ 纹理。水面倒影雾、视距检查和部分全分辨率补算使用噪声均值。

`fogdata.bin` 格式版本为 4，保存光源、光源参数和辉光、雾效关键帧、雾层、区域光轮廓及调色曲线。噪声列映射和午夜前后的调色插值为推算结果。资料包中每个已布置灯光使用的 32³ LUT 对 RGB 三通道应用同一条曲线，因此只保存 32 个值。

### Forever 水面数据

`tools/convert_forever_water.py` 从 Forever 水面资料包读取 `LiquidType`、`LiquidTypeXTexture`、`LiquidTypeXFFTTile`、`FFTTile` 和 BLP 泡沫纹理，核对 SHA-256 清单后生成 `data/waterdata.bin`。

```powershell
python tools/convert_forever_water.py <资料包目录或ZIP> data/waterdata.bin
```

数据包含四个预设（湖泊 1240、河流 1288、海洋 1250、室内 WMO 水域 1290）、七个 FFT 图块，以及六张带完整 mip 链的 1024² 泡沫遮罩。CPU 到 GPU 的字段映射根据取值范围和着色器推算。吸收由 `-ln(Color[0])` 和 `Float[0]` 决定，浪尖和波谷的散射颜色取自 `Color[1]`、`Color[2]`。深度、岸边和波浪泡沫用 `Float[7..19]`，日光和倒影粗糙度用 `Float[27]`、`Float[29]`，倒影强度用 `Float[30]`。FFT 图块 0–3 字段控制尺寸、振幅、风向对齐和倍率，4–9 字段控制泡沫与含氧变化速率。

## 客户端加载与挂钩

- **加载器**通过代理 `version.dll` 的静态导入加载 `CoAVolFog.dll`，17 个导出函数延迟转发到系统库。
- **D3D9 设备**通过延迟加载的 `GetProcAddress` 槽 `[0xB2ED98]` 返回包装后的 `IDirect3D9`。DXVK 等 D3D9 封装仍在底层工作。单采样时绑定 `INTZ` 深度纹理，多重采样通过自检时保留原版多重采样后缓冲，并用 `INTZ` 接收深度副本。
- **场景与雾效**挂钩位于 `0x4FB03D`（场景渲染和原版雾管理）、`0x4F911D`（不透明 M2 后捕获输入）、`0x4F9170`（液面深度）、`0x7E5818`（场景名字的深度保护）和 `0x4F9281`（屏幕特效前绘制雾）。`FarClipMax` 使用独立的 `0x780810` 和 `0x781444`。
- **半透明雾与水面**分别检查 M2 批次 `0x81FD15`、眩光 `0x4F9213`，以及水面处理 `0x790AA2` 和材质虚表 `0xA5954C`、`0xA59580`。安装前核对原始字节。水面挂钩成功后才加载水面数据，水面异常时恢复设备状态并在本次会话关闭水面。
- **状态和输入**用状态块保存并恢复渲染状态，同时恢复渲染目标、深度和流 0 的偏移。设置窗口在 `Present` 阶段绘制，并在设备重置前释放资源。光标位于窗口内或从窗口开始拖动时才截获鼠标操作，只有编辑框激活时截获按键。设置窗口异常会记录日志并在本次会话关闭。

客户端地址对应 12340 的映像基址 `0x400000` 和时间戳 `0x4C2452FE`。Gx 设备位于 `[0xC5DF88]`。下面列出主要输入，供定位日志和核对客户端版本。

### 客户端逆向记录

- **场景入口与调用约定**。场景入口 `0x4FB03D` 的原始字节为 `E8 5E DE FF FF`，调用 `0x4F8EA0`，入口保留 ECX。不透明 M2 的 `0x4F911D` 调用 `0x823CB0`，采用带一个栈参数的 thiscall。液面 `0x4F9170` 调用 `0x77F020`，帧特效结束入口 `0x4F9281` 调用 `0x8C1010`。
- **延迟加载与投影**。磁盘映像中的 `[0xB2ED98]` 指向延迟加载桩 `0x41C654`。模组只在该槽仍指向原始加载桩时安装替代入口。`0x6821A4` 读取相对镜头的视图和投影矩阵，`0x6BF370` 生成 OpenGL 深度范围的投影，D3D 后端再转换。场景视口的 MaxZ 为 0.94，`0x6A9ACC` 将它写入 D3D9 视口。超出此范围的深度用于区分远处地形和天空。
- **抗锯齿、液体深度与名字**。视频菜单的采样列表 `0x54F1B0` 在每次进程启动时生成一次，并由包装的 `CheckDeviceMultiSampleType` 过滤。`gxMultisample` 会请求 `gxRestart`。强制水面深度写入期间，包装器记录客户端最后请求的 `D3DRS_ZWRITEENABLE` 并在结束后重放。`0x7E5818` 调用场景字体批次，模组保留深度测试并避免名字污染用于雾效的深度。
- **场景顺序、眩光和天气**。原版先画天空、WDL、地形和 WMO，再画 M2。不透明 M2 后，水面上下的后续 M2、天气和液体顺序不同。原版眩光 `0x7F0870` 会查询遮挡，并以叠加方式绘制日月贴图。天气使用自身淡出，或 70–75 码的灰雾。
- **M2 批次雾**。`0x81FB10` 根据混合模式选雾色。`0x873210` 写入像素常量 c2，以及顶点常量 `c30 = (−1/(end − start), end/(end − start), exponent, 0)`。这些调用决定了半透明雾所用的线性视深和混合色。
- **Extensions.dll 与辉光**。Ascension 的扩展 DLL 会改写眩光、光源参数、M2 与昼夜流程，`ambientGlow` 可使辉光强度超过 1。客户端 `0x4F8770` 将辉光量写成 `floor(255·g) mod 256`，因此补偿按实际传入的字节计算。客户端的着色器加载器只接受 BLS `0x10003`，此版本的 FFXGlow 回退到 ps_2_0，最终合成回后缓冲。角色名字和图标在帧特效结束后绘制。
- **地图、光源槽与视距**。地图切换加载界面在 `0x40AD50` 写入 `[0xAB63BC]`，部分退出路径将其设为 −1。`0x7EB180` 从 Light 记录的 `+0x1C + 4·slot` 读取参数，昼夜系统更新风暴权重。`0x780770` 的视距范围约为 183.33–1583.33 码，模组在 CVar 设置及地图加载处挂钩，并兼顾扩展 DLL 在切换区域时的调用。
- **设置窗口绘制与输入**。D3D9 后端通过 Gx `+0x397C` 的设备调用 `Present`。D3D 窗口过程 `0x6A0360` 将键鼠消息交给 Gx 输入回调。模组在该链路处理设置窗口热键和鼠标操作。
- **点光源和室内**。M2 场景使用 64×64 的点光源表，每格按世界坐标 20 码分桶。WMO 实例、活动组和组数用来判断镜头所处的室内空间。读取前核对客户端映像和相关指令，并用 SEH、指针范围及数量上限约束读取。
- **水面与水域分类**。`0x77F020` 经 `0x790A80` 在 `0x790AA2` 调用液体渲染器 `0x8A2240`，thiscall 以 `ret 8` 返回。液体设置表 `0x8A28F0` 将绘制使用的设置对象映射回液体类型。分类还读取纹理、材质和声音类别，以区分湖泊、河流、海洋和室内水域。
- **单位接触、原版水花与水色**。可见对象链表从对象管理器的 `+0xAC` 开始。世界实体的位置和液面高度用来判断单位是否与水接触。`waterRipples` 的写入位置是 `0xADF7F0`，读取处 `0x79D463` 会在值为 0 时跳过生成贴图。水色取自 DayNight 近色和远色，水面使用场景直射光，日月颜色项仅为贴图着色。

## 测试与性能测量

完整的 `ctest` 运行注释检查、室内雾过渡和 INI 保存测试，以及使用真实 D3D9 设备的 `vfog_harness`。后者覆盖状态恢复、深度与天空、经典版光照混合、光线积分、时域滤波、上采样、室内雾、设置窗口、设备重置、水面分类、FFT、模板缓冲、半透明雾、辉光、调色和涟漪。可在 `build/harness-out` 查看 `before.png`、`after.png`、`overlay.png` 和调试视图。CI 的 `-LE gpu` 检查无需显卡，游戏画面和帧率需实测。

从项目根目录运行以下示例，`<输出目录>` 替换为实际路径。

```powershell
build/Release/vfog_harness.exe --scene harbour <输出目录> --data data/fogdata.bin
build/Release/vfog_harness.exe --scene ripples <输出目录> --water-data data/waterdata.bin
build/Release/vfog_harness.exe --scene performance
```

- `harbour` 重现暴风城港口的日落场景（约 791.6 码视距），对照 CPU 积分输出探测点的雾不透明度和颜色。可加 `--classic-phase 1` 或 `--storm 1`。
- `ripples` 生成静止、走路、跑动、游泳和入水的水面效果，并输出法线和平静水面对照。
- `performance` 在 1920×1080 下测不同画质、局部光源、暴风城港口、风暴和调色的 GPU 耗时，输出 `quality,case,point_lights,median_ms,p95_ms`。加 `--samples 4` 可尝试使用 4 倍多重采样。

## Steam Deck 与 Linux（Proton）

安装模组文件后，在 Steam 启动选项填写：

```sh
WINEDLLOVERRIDES=version=n,b %command%
```

这会优先加载代理 `version.dll`。原项目于 2026 年 10 月 8 日在 Steam Deck（AMD VanGogh、1280×800、Proton + DXVK）验证了 DLL 加载、挂钩及通过 `RESZ` 向 `INTZ` 复制深度。测试场景在 `Quality=2` 和 2 倍多重采样下维持 60 FPS，GPU 使用率 69%、914 MHz、2.8 W。8 倍时，雾和水面的 GPU 中位耗时分别为 6.47 ms 和 2.81 ms，GPU 使用率 97%、1600 MHz、8.3 W。数据只计入该场景的特效耗时。其他硬件、Proton 和 DXVK 版本的表现需要另行验证。

## 日志与故障排查

- **雾效摘要**在 `LogLevel=1` 时记录首帧、视口或视距变化，以及每 60 秒一次的统计。`LogLevel=2` 额外每 600 帧记录一次。`fog gpu` 是雾与阳光光束的 GPU 中位耗时。`skipped` 表示丢失计时结果的帧。经典版数据启用时还会记录辉光、调色曲线采样和噪声雾层。
- **水面摘要**每 60 秒记录 GPU 耗时、水域类别、FFT 尺寸和图块数，以及涟漪尺寸、更新频率、单位接触数和丢弃步数。初次遇到某类液体时会记录其分类。`water idle` 表示视野里没有水面、镜头位于水下等情况。
- **深度探测**在第 60 帧记录 25 个点的原始深度、距离和雾不透明度，随后每 60 秒再记录，最多五次。`LogLevel=2` 时改为每 30 秒一次，次数不限。`fog skipped: <reason>` 会记录跳过绘制的原因。
- **设备诊断**在创建设备和 `Reset` 时记录显卡、请求和实际使用的采样数、深度格式、复制方式及自检结果。客户端字节校验不符时也会说明受影响的功能。
- **设置变动**在设置窗口的修改稳定、INI 重载或点击还原后写入一条日志，例如 `settings: WaterFoam 1 -> 1.5, WaterWind 2 -> 4`。

## 已知限制

- 体积雾以旧客户端的光照和可用深度为输入，当前场景几何不会为雾中的阳光投下阴影。远景雾是用于旧客户端视距边界的近似效果。
- 局部点光源来自当前 M2 场景，没有聚光灯锥或局部阴影。影响半径上限为 200 码，只有 WMO 提供的光源覆盖仍待验证。
- 部分像素着色器超过基础 Shader Model 3.0 保证的 512 条指令。调低画质不会降低该要求。如果显卡缺少必需的着色器能力，会退回原版雾，日志中会记录着色器名称、HRESULT 和能力值。
- 室内过渡跟随镜头位置，从门窗向外看时，雾效可能与逐房间计算不同。半透明雾使用拟合的线性曲线，远处粒子或辉光可能更早消失。
- 多重采样可平滑轮廓，但带 Alpha 测试的植被边缘仍可能有锯齿。提高大陆视距可能使加载的地形增至约四倍，增加 32 位进程的内存用量。
- 水面几何保持平坦，波浪由着色模拟。屏幕外倒影使用天空作为补充。客户端缺少河流流向图，河流泡沫采用当前预设。熔岩、软泥和水下视角使用客户端效果。
- 涟漪只模拟一定范围内最近的 32 个单位。关闭原版水花后，范围外的单位也可能看不到尾流。客户端脚步溅水与船只等游戏物体的尾流尚未接入。
- Forever 噪声字段、部分水面参数及 `ClassicPhase` 的归一化由数据和着色器推算。辉光与调色的效果也受旧客户端光照流程影响。
